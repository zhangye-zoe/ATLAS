# Phase-wise T3 Monitoring and Early Stopping

## Evidence and motivation

On PBMC 0% paired, 1224 valid stage-labeled cells, seed 1234:
- TimeHead: 2/1/1 epochs -> POA 0.6528, POAUC 0.7519.
- TimeHead: 80/60/40 epochs -> POA 0.5092, POAUC 0.3176.
- Consensus: 2/1/1 epochs -> POA 0.6198, POAUC 0.7600.
- Consensus: 80/60/40 epochs -> POA 0.5835, POAUC 0.7401.

These measurements suggest possible training-associated T3 degradation,
but do not prove that short training is inherently optimal: all three
training phases changed and there is only one seed.

## Protocol

The new opt-in early-stopping configuration uses:
- Epoch-wise monitoring every 5 epochs and at all phase ends.
- Monitor stage labels for **supervised checkpoint selection only**;
  stage labels NEVER enter model training losses/temporal teacher.
- A deterministic, stage-stratified 30% monitor / 70% report partition.
- A separate held-out report LABEL set, whose stage labels do NOT select epochs.
- The same T3 inference estimator for selection and final report.
- A checkpoint of the best monitor POAUC **across all phases**.
- Optional stopping of Phase III after repeated non-improving checks,
  subject to a minimum number of Phase III epochs.
- Always restore best checkpoint before final evaluation and saving model.pt.

Important scientific qualifications: This is supervised model selection
on stage annotations, not a label-free time estimation protocol.
Time inference uses ALL 1224 cell input features under the existing
transductive benchmark protocol, so the graph and model input cohort are
identical in monitor/report inference. Only stage *labels* are disjoint.
The final pseudotime DIRECTION is frozen using monitor labels, not chosen
using report labels. Since final T3 scoring uses ~70% instead of all 1224
reference labels, do not directly compare its numerical values to older results.
Using held-out unlabeled input profiles in the inference graph is TRANSDUCTIVE,
not an inductive generalization evaluation. This assumption must be disclosed.

## Parameters

```yaml
early_stopping:
  enabled: true
  monitor_fraction: 0.30
  metric: POAUC
  eval_every: 5
  patience: 4
  min_delta: 0.002
  min_phase3_epochs: 10
```

Patience is measured in CHECKS (not epochs). At eval_every=5,
patience=4 means ~20 Phase III epochs without a meaningful score increase.
The first two phases still train their full 80 and 60 epochs but are also
monitored; the best checkpoint can be from Phase I, II, or III.

## Outputs

- `t3_validation_partition.json`: exact disjoint monitor and report label IDs.
- `t3_monitor_history.json`: phase, epoch, POA/POAUC, best so far.
- `best_t3.pt`: best checkpoint using monitor labels only.
- `checkpoint_phase1_last.pt`, `checkpoint_phase2_last.pt`,
  `checkpoint_phase3_last.pt`: end-of-phase diagnostic snapshots.
- `early_stopping_summary.json`: selected phase/epoch and stop cause.
- `model.pt`: selected checkpoint loaded for final reporting.
- `metrics.json` and `summary.csv`: T3 on held-out report labels, with the time direction fixed by monitoring labels. T1/T2 still use the full validation cohort.
- `t3_monitor_curve.png`: generated by optional plotting script.

The existing `restore_t3_metrics.py` is not appropriate for writing new
scores on these outputs because it uses a different annotation-rescoring
protocol and may overwrite T3 scoring metadata.

Early stopping is opt-in: existing model configurations without
`early_stopping.enabled` run as before.
